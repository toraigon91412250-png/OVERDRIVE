# 進撃モード改善記録

基準版: 4ea78a8 / 公開87。ユーザー指定により50点を起点にする。
採点はコードと実行検証に基づく技術レビュー。楽しさの実測や第三者評価ではない。

固定配点: 安定性25、戦闘25、操作20、視認性15、性能15。
初期内訳: 12 / 12 / 11 / 9 / 6 = 50。
ブラウザ実画面で検証できない項目は加点しない。描画・体感に関わる未確認分を残す。
各ループは問題点→採点→変更→実行検証→残課題の順に記録する。

ブラウザ確認を準備したが、正規CUAランタイムはtrusted browser serviceの設定不足で開始できず、Sites preview relayも失敗。別のブラウザ経路への置き換えは行わず、実ジオメトリ・GLTF解析とゲームシミュレーションで確認する。

## 1. 再出撃と切り替えの安定性: 50 → 54 (16/12/11/9/6)
問題: 再利用モデルが以前の親の拡大率を引き継ぐ。超大型用開始地点が通常リセットで上書きされる。失敗した読み込みがキャッシュに残る。
実装: 読み込みモデルを親から切り離して正規化。リセット末尾で種類別の開始状態を復元。無効ID拒否、古い非同期応答の無視、失敗キャッシュ削除。
検証: 4種を3周切り替えた実寸と無効ID拒否、超大型の実際の出撃位置を追加検証。ビルドとモデル統合テスト通過。
残課題: 動く頭と当たり判定、ワイヤー追従の更新順。

## 2. 動く部位と接続点: 54 → 59 (16/15/13/9/6)
問題: うなじと装甲判定が本体ルート固定。物理計算の後に敵と接続点を更新しており追従が遅れる。
実装: うなじを実際の頭グループ、肩判定と装甲表示を肩グループへ接続。元のスケールを維持する脈動に変更。敵と接続点を物理計算前に更新。再選択時に生成判定を除去。
検証: 実GLTFで頭への接続と基準スケールを確認。モデル切り替え、雷槍の肩命中、うなじ討伐、動く接続点のテスト通過。
残課題: 生成ジオメトリの破棄と弾体の再利用。

## 3. 繰り返しプレイのメモリ管理: 59 → 63 (16/15/13/9/10)
問題: 標的切り替えごとに生成した判定や装甲ジオメトリが未破棄。発射時に仮弾体を作って直後に捨てる。爆発の球・リングも毎回新規ジオメトリ。
実装: 生成判定・表示を切り替え時に破棄。読み込んだ弾体を直接複製しジオメトリを共有。爆発ジオメトリを共有、個別の爆発マテリアルは終了・リセットで破棄。
検証: 破棄イベントと複数弾のジオメトリ共有を実物で確認。装甲への実際の発射も通過。
残課題: 壁越しの攻撃と、雷槍だけで討伐が完結する戦闘。

## 4. 戦闘ルールと遮蔽: 63 → 68 (16/20/13/9/10)
問題: 雷槍だけで倒せるため背後へ斬り込む必要が薄い。巨人だけへのレイ判定で建物越しにロック・斬撃が成立する。
実装: 雷槍はうなじ8ダメージ、最後の1は刃でのみ討伐。雷槍の装甲破壊能力と刃3回の救済は維持。建物で遮蔽判定、外れた雷槍も手前の景物で爆発。遮蔽物一覧をルートごとにキャッシュ。
検証: 装甲の雷槍命中と背後からの刃討伐を含む統合テスト通過。複数標的の既存ルールに回帰なし。
残課題: 敵ごとの攻撃が旧地面攻撃と重なり、顎の噛みつきが全方向に当たる。

## 5. 敵の予兆と反撃時間: 68 → 72 (16/23/13/10/10)
問題: 新AIと旧地面攻撃が重複。顎の噛みつきに背後の安全地帯がない。空中では一部の巨人に対して常に安全。
実装: 4種類共通の予兆→一回の攻撃判定→硬直→待機を専用モジュール化。顎の前方噛みつき、通常大型の対空腕払い、超大型の蒸気を範囲・高さ別に判定。予兆中は向きを固定し背後への回避を成立させる。
検証: 種類ごとに初動の猶予、一予兆につき一判定、範囲外の安全、顎の背後回避、対空腕払い、リセットを実行確認。モデルとゲームの統合も通過。
残課題: タブ移動・ポインターロック喪失中にもゲームが進む。

## 6. フォーカス喪失と再開: 72 → 77 (18/23/16/10/10)
問題: 別ウィンドウや非表示タブでも敵の攻撃が進み、ポインターロック解除後の復帰も不明確。
実装: フォーカス・ロック喪失・非表示で入力解除と一時停止。中央の再開表示をクリックすると復帰し、時間差を蓄積させない。設定画面・リセットとも状態を整合。
検証: ガス入力中にblur→1秒進めてもシミュレーション時刻不変→表示から再開→時刻が正常に進むことをゲーム本体で確認。従来のPC/タッチ入力テストも通過。
残課題: 巨人の体を高速ですり抜ける。

## 7. 巨人の体との衝突: 77 → 81 (20/23/18/10/10)
問題: 巨人の体と頭をすり抜け、高速接近時に自分と敵の位置関係が崩れる。
実装: 胴・頭に軽量な楕円体の連続衝突判定を追加。前位置からの移動経路で貫通を防ぎ、接線方向の速度を保ちつつ体へ向かう速度を除去。頭の判定は動く頭グループに追従。
検証: 高速で反対側へ移動するケース、かすめる移動、内部からの復帰、回転・拡大した巨人での衝突を確認。従来の離陸・滑空・ワイヤー操作も通過。
残課題: 命中や攻撃可能距離の表示、討伐結果の情報が不足。

## 8. 命中・攻撃圏・結果: 81 → 84 (21/23/18/12/10)
問題: 命中したか、近接攻撃できるか、討伐に何秒かかったかが分からない。終了時に予兆や飛翔体が残る。
実装: 既存照準の短い命中表示とうなじ斬撃圏表示、日本語の装甲状態を追加。討伐時間・最高速度・被弾・雷槍使用数と巨人別ベストタイムを記録。終了時に予兆・飛翔体を除去。
検証: 討伐後の結果文とベスト記録をゲーム本体で確認。装備・討伐・再出撃の統合を再検証。画面上の見え方は未確認のため視認性を満点にはしない。
残課題: ワイヤー描画の大量一時ベクトル、装備の細かい描画単位、公開メニューの初回読み込み量。

## 9. 描画と読み込みの負荷: 84 → 88 (21/23/18/12/14)
問題: 装備に799個の描画用メッシュ。ワイヤー分割ごとの一時Vector3。公開メニューにも全巨人と演出のデータを埋め込む。
実装: 元HTMLの材質別結合をアニメーション境界を保って適用。ワイヤーと照準レイの作業オブジェクトを再利用。公開メニューは同一サイトの進撃HTMLを必要時に読み込み、ダウンロード用HTMLは従来どおり単体動作。
検証: 実装備で799→127メッシュ(約84%減)を確認。公開index約9MB→約1MB。単体HTMLの内蔵モデルと演出は保持。飛行、当たり判定、モデル切り替え、結果表示が通過。FPS向上値は未計測のため主張しない。
残課題: 設定が保存されない。ブラウザの古いPointer Lock API・失敗時の復帰、読み込み再試行の扱い。

## 10. 設定・API互換・復帰: 88 → 91 (24/23/18/12/14)
問題: 毎回装備や設定を入れ直す。保存が壊れた/禁止された環境への配慮がない。旧Pointer Lockのvoid戻り値で例外、拒否時にも進行。読み込み失敗後に再試行UIがない。
実装: 設定・標的・携行数を検証付きで保存復元。音量/消音を追加。保存領域へアクセス自体が拒否されても継続。Pointer Lockのvoid/Promise/同期例外に対応し失敗時は停止。読み込み再試行を追加。演出の二重起動を防止。最後の被弾・使用数を結果確定前に反映。
検証: 壊れたJSON、範囲外設定、保存拒否、音量0、ベストタイムを確認。ゲーム本体でPointer Lockのvoidと拒否を再現。雷槍6発で残りHP1になり、刃でのみ討伐できること、正面からの斬撃拒否、建物でのロック遮蔽も追加確認。旧速度テストはユーザーが後から採用した標準高速設定へ期待範囲を更新し、実速度61.31m/s、位置変化63.86m/s、水平ガス1秒34.64m/sで通過。飛行の数値そのものは変更していない。
残課題: 実ブラウザのWebGL描画、音の印象、操作感の人による評価。これらは未確認のため減点として残す。
